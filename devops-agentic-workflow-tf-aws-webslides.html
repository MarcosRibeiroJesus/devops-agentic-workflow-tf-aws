Comparando

Tradicional vs. Agêntico

Tradicional

  • Foco no engenheiro está na sintaxe
  • Cada provider/módulo exige pesquisa manual
  • Revisão de segurança compete com prazo
  • Conhecimento fica na cabeça de poucas pessoas

Agêntico

  • Foco do engenheiro está na decisão
  • Agente conhece a sintaxe e as convenções do time
  • Segurança revisada antes de qualquer apply
  • Contexto vive em arquivos versionados: CLAUDE.md, rules, skills

Skills

Lida em duas camadas: nome e descrição no início da sessão; corpo completo só quando invocada.

Procedimentos reutilizáveis que carregam sob demanda.

Analogia

Saber configurar uma GitHub Action do zero é uma skill de CI/CD. No Claude Code funciona igual: um dev sênior grava o passo a passo uma vez, e o time todo (o próprio Claude incluído) reaproveita só quando o trabalho pedir exatamente aquilo.

Agents (subagents)

Chamado sob demanda: automaticamente pelo Claude, ou explicitamente por você. Cada um roda em contexto isolado.

Instâncias isoladas para tarefas paralelas e especializadas.

Agente principal

Analogia

É como montar um time: em vez de uma pessoa só fazer tudo, você chama um especialista pra revisar segurança e outro pra documentação, cada um isolado, devolvendo só o resultado final.

01 · Fundamentos

Rules

Lida sempre, ou só quando um arquivo bate no padrão de caminho (paths) da regra.

Convenções carregadas só quando relevantes.

Analogia

É como uma regra de lint aplicada só a um diretório do repositório: sempre que alguém mexe em infraestrutura, a convenção dispara sozinha, sem precisar repetir pra ninguém em cada PR.

"hooks": {
  "PreToolUse": [{
    "matcher": "Bash",
    "command": "block-destroy.sh"
  }]
}
hard: o harness aplica sempre
02 · Segurança

Hooks

Automação determinística em pontos do ciclo de vida do agente.

.claude/settings.json · exemplos de hooks para DevOps
// 1. Bloquear comando destrutivo antes de rodar
"PreToolUse": { matcher: "Bash(terraform destroy*)", command: "deny" }

// 2. Formatar automaticamente depois de editar .tf
"PostToolUse": { matcher: "Edit(*.tf)", command: "terraform fmt" }

// 3. Validar credenciais AWS antes de começar a sessão
"SessionStart": { command: "check-aws-profile.sh" }
02 · Segurança

Permissions

O que o agente pode, não pode, ou precisa perguntar.

.claude/settings.json
{
  "permissions": {
    "allow": ["Bash(terraform plan)", "Read(./infra/**)"],
    "ask":   ["Bash(terraform apply)"],
    "deny":  ["Bash(terraform destroy *)", "Bash(aws iam create-user *)"]
  }
}
02 · Segurança

Guardrail na prática

Bloqueando comandos destrutivos antes que aconteçam.

settings.json → hooks.PreToolUse
$ terraform destroy -auto-approve
